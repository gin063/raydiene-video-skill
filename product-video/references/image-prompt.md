# 图像 prompt · 写法

首帧和尾帧共用这一套规则。尾帧的写法见 `frame-strategy.md` 第 4 节——**复制首帧，只改变化的那几句**，本文的十三要素只在写首帧时逐条走一遍。

---

## 0. 语言与形态

**用中文写，专业摄影术语中英并置。**

```
浅景深 shallow depth of field，f/1.8，焦平面落在枪头卡扣上
侧逆光 rim light 从画面左后方 45° 打入，勾出桩体右缘轮廓
```

三个理由：画面内文字本来就是中文；产品参考句是中文；而术语挂英文原词是因为部分图像模型对 `Rembrandt lighting`、`f/1.8`、`85mm` 这类词的响应比中译准。两边都给，操作者按模型表现取舍。

**写成结构化散文，不要写 JSON。** 图像模型的文本编码器训练在自然语言图注上，不是键值对。更实际的风险是**渲染污染**：JSON 的键名、引号、方括号会被直接画进图里，而且模型越擅长渲染文字，这个风险越高。

分段标题（`【主体】`这类）可以用来组织长 prompt，但要在禁止项里明写「不要把任何标签名、方括号、引号画进画面」。

---

## 1. 十三要素

一段完整的图像 prompt 应当覆盖以下十三项。**不是每项都要写满**，但每项都要**想过**——想过之后判断「这镜不需要」和压根没想到，出来的图差很远。

### ① 画幅与定格声明
比例（`16:9 横画幅` / `9:16 竖画幅`）。加一句 **`静止定格画面 still frame`**——这是在告诉模型这是一帧而不是一段动态的示意，能显著减少模型自作主张加运动模糊。

> 🔴 **首帧不写运动模糊。** 现象还没开始，没有可模糊的东西；写了会让视频模型把「已经在动」当成既成事实。尾帧若现象仍在持续（如水还在流），可以给轻微动态模糊。

### ② 画风轨道
四选一，见第 3 节。**同一镜只能锁一条**，混着写会得到四不像。

### ③ 主体与此刻状态
主体是什么、在画面里占多大、**此刻处于什么状态**。状态是首尾帧的全部意义所在，要写得具体到可验证：不是「灯是灭的」，是「指示灯完全熄灭，灯罩内可见未通电的灰暗导光柱」。

### ④ 场景与时空
地点、时段、天气、周边陈设。地下车库要交代层高、柱距、地面材质、顶部管线；露天车位要交代天光、墙面、地面排水。**环境的具体程度决定真实感**——空荡荡的灰背景一眼是渲染图。

### ⑤ 景别与机位
- 景别：大特写 ECU / 特写 CU / 近景 MCU / 中景 MS / 中远景 MLS / 全景 WS / 大全景 EWS
- 机位高度：平视 eye level / 低角度仰拍 low angle / 高角度俯拍 high angle / 顶视 overhead / 斜角 dutch angle
- 与主体的距离和方位角（正面 / 偏左 15° / 侧 45° / 背侧）

### ⑥ 镜头焦段与透视
| 焦段 | 观感 | 适合 |
|---|---|---|
| 14–24mm 超广角 | 空间夸张、边缘变形 | 车库全景、强调环境 |
| 35mm | 接近人眼、轻微环境交代 | 安装过程、人物在场 |
| 50mm | 中性无畸变 | 产品正面、纪实感 |
| 85mm 中长焦 | 压缩空间、背景虚化 | 产品特写、人物半身 |
| 100mm 微距 macro | 极浅景深、结构毕现 | 触点、芯片引脚、螺纹 |
| 135mm+ | 强压缩 | 远距离压缩透视 |

焦段和景别是两件事。**同样的构图，24mm 贴近拍和 85mm 退远拍，透视完全不同**——写清楚哪一种。

### ⑦ 光圈与景深
写 f 值 + **焦平面落在哪** + 焦外怎么衰减。`f/1.4` 到 `f/16` 是完全不同的叙事：大光圈是「只看这里」，小光圈是「全都要看清」。

技术拆解镜头常需要 `f/8 全景深 deep focus`，因为结构就是内容；产品情绪镜头则相反。

焦外质感也可以指定：`奶油般柔滑的焦外 creamy bokeh` / `二线性焦外` / `圆形光斑 circular bokeh`。

### ⑧ 布光
最能拉开差距的一项，也是最常被写漏的。至少交代**主光方向 + 光质 + 反差**：

- 光位：顺光 / 侧光 45° / 侧逆光 rim light / 逆光 backlight / 顶光 / 底光
- 光质：硬光 hard light（清晰硬边影子）/ 柔光 soft light（柔和过渡）
- 布光法：三点布光 three-point、伦勃朗光 Rembrandt、蝴蝶光 butterfly、分割光 split、明暗对照 chiaroscuro
- 修饰：柔光箱 softbox、反光板补光 bounce fill、负补光 negative fill（加深阴影）
- **场景光源 practicals**：车库顶灯、车灯、手机屏、桩体自身指示灯——写出来才有动机光 motivated lighting，画面才像真的

**光比要给个感觉**：`高反差，暗部几乎不留细节` / `低反差，阴影通透`。

### ⑨ 色温与调色
色温开尔文值（`3200K 暖钨丝` / `5600K 日光` / `7000K 阴天冷调`）、整体色调倾向、对比曲线、高光滚降 highlight rolloff。

混合色温是真实感的来源：`车库顶灯 4000K 冷白与车尾灯暖红混合，形成冷暖对冲`。

### ⑩ 构图
三分法 rule of thirds、引导线 leading lines、对称、负空间 negative space、框中框 frame within frame、前景遮挡 foreground occlusion、头顶留白 headroom、视线留白 lookroom。

🔴 **构图是运镜的载体。** 首尾帧的构图差值就是运镜（`frame-strategy.md` 第 7 节），所以这一项在尾帧里**是允许改的少数几项之一**——但必须是有意为之的改，不是随手改。

### ⑪ 质感与介质
数字/胶片、颗粒 grain、锐度、色散 chromatic aberration、光晕 halation、暗角 vignette、镜头眩光 lens flare。

写实轨道值得加 `轻微感光度颗粒` 之类——**过分干净就是渲染图的味道**。

### ⑫ 画面内文字
🔴 **要渲染的文字用「」括起来，单独成行，逐字写全。** 这是模型区分「要画上去的字」和「描述用的字」的唯一依据。

```
桩体屏幕显示「已连接」
图标下方一行小字「接地正常」
```

数字、单位、标点全部锁死，不要写「显示功率数值」这种。**不要因为担心模型写不准就绕开中文**——按最理想效果写，人工审核会兜。

### ⑬ 禁止项
只禁两类：**prompt 残留**和**画面里不该有的具体东西**。

```
不要把任何标签名、方括号、引号、prompt 中的说明文字画进画面；
不要出现可读的车牌号、他人小区或门店名称；
不要出现未在上方指定的任何文字或数字；
不要出现乱码文字；
不要新增未指定的 logo、品牌文字、产品标签或水印。
```

> ⚠️ **不要写笼统的「无多余文字 no extra text」。** 它会连场景里天然该有的标识一起禁掉——车库层号 B1、车位编号、限高牌、地面导向箭头。**那些恰恰是真实感的来源**，一个没有任何标识的地下车库看着就是渲染图。
>
> 判定标准：**这段文字是画面里本来就有的东西，还是画上去的东西？** 前者留，后者禁。

## 2. 产品参考句

镜头里出现真实产品时，在描述该产品的位置**紧跟一个括号**，内容逐字照抄：

```
一个壁挂式充电桩（参考已上传图像中的产品外观，严格保证产品logo、配色、比例、外观细节等不变）
```

四条约定：
- **只在产品实体出现时加**。空镜、纯图形动画、不含产品的特写不加
- **括号紧跟在产品名词后面**，不要挪到 prompt 末尾——离得远了约束会被稀释
- **不指定用哪张参考图**。选图是操作者的事
- **尾帧照写**，不能因为首帧已经有了就省

产品的**局部**（继电器、主控芯片、枪头、屏幕）如果参考图里有对应画面，同样加这句；参考图里没有的内部结构，不加——加了等于让模型去「参考」一张不存在的图。

### 这句话在约束什么

括号里那句是简写。模型真正要锁住的是六项，写 prompt 时心里要清楚是哪六项，
挑图和验收时才知道看什么：

| 锚点 | 要求 |
|---|---|
| 主体识别度 | 产品轮廓与结构必须可识别为同一款 |
| 色彩气质 | 主色、辅色、点缀色的关系不变 |
| 材质逻辑 | 塑料、金属、玻璃各自的表面响应不变 |
| 光影逻辑 | 主光、辅光、阴影、反射的层次气质延续 |
| 构图记忆点 | 最强视觉重心、轮廓、形状张力保留 |
| 情绪基调 | 冷/暖/高级/趣味的方向不变 |

**锚定 ≠ 复刻原图构图。** 参考图是视觉基因来源，不是每个镜头的画面牢笼——
镜头该用什么机位就用什么机位，锁的是上面六项，不是把原图再画一遍。

### 参考图不止一张时

Kling 3.0 的 Element Reference 与即梦的「全能参考」都支持 **2–4 张参考图绑定主体**，
一致性明显强于单图。产品有多角度图时优先走这条，别只挂一张。

### 按模型追加 @ 引用

两家都支持在正文里 `@` 引用已上传/已绑定的素材，比再描述一遍外观稳得多：

| 模型 | 写法 |
|---|---|
| Kling | `@产品` `@Image`，如 `中景，背景 @Image，@产品 固定在墙面上` |
| Seedance | `基于上传的[图片]，严格保持@图1的[外观/配色/logo]一致，严格锁定[比例与细节]` |

Seedance 官方明说**全文可以多次 @**，会更准。

### 产品主体的造型公式

Seedance 官方给了非人物主体的描述公式，写产品时按它排能少漏东西：

> `[数量词] + [颜色] + [外形/设计风格] + [具体物品名词] + [材质细节/磨损状态] + [标志性特征]`

例：`一台 / 哑光白配深灰 / 极简方正壁挂式 / 家用交流充电桩 / 表面细磨砂无划痕、边缘倒角 / 正面下方横向指示灯带`。

再跟上产品参考句，两者是互补的：公式管「说清楚」，参考句管「别改」。

## 3. 四条画风轨道

每条轨道有自己的词库。**锁死一条，整段 prompt 的措辞都从这条轨道里取。**

### A · 写实摄影 photorealistic
安装过程、使用场景、环境镜头。

关键词：`真实摄影`、`自然光`、`浅景深`、`轻微感光度颗粒`、`皮肤/金属/混凝土的真实材质`、`纪实感`。

⚠️ 这条轨道的敌人是「太完美」。加一点不完美——地面的水渍、墙面的施工痕迹、线缆的自然垂坠——反而更真。

### B · 3D 技术演示 technical 3D
拆解、爆炸视图、剖面、内部结构。

关键词：`高精度 3D 渲染`、`爆炸视图 exploded view`、`剖面 cutaway`、`产品可视化 product visualization`、`工作室布光 studio lighting`、`纯色/渐变无限背景 seamless backdrop`、`次表面散射`、`物理渲染 PBR 材质`。

🔴 **3D 轨道同样要写机位、焦段、光圈、布光。** 渲染器吃这些词，写了才有电影感；不写就是默认摄像机 + 默认灯光，出来是电商白底图的味道。

⚠️ 拆解镜头的结构必须物理成立——见 `physical-realism.md` 第 3 节。

### C · 2D 动态图形 motion graphics
图标、监测线路、数据跳动、UI 演示。

关键词：`扁平矢量`、`等距 isometric`、`描边图标 line icon`、`发光路径 glowing path`、`纯色背景`、`极简信息图`。

这条轨道**不写焦段和光圈**（没有物理镜头），但要写：线条粗细、圆角半径、配色（给具体色值）、发光扩散范围、图标风格是否统一。

⚠️ 一整支片子里的图形轨道镜头，**配色和图标风格必须逐字复用同一段描述**，否则每镜一个样。

### D · 混合 hybrid
写实底 + 图形叠加。桩体实拍质感，上面浮着监测图标和数据。

写法是**分层描述**：先按 A 轨道写实拍层，再单起一段写叠加层（位置、透明度、发光、与底层的遮挡关系）。

⚠️ 必须交代**叠加层的空间关系**：是贴在桩体表面（跟随透视），还是浮在桩体前方的空中（正对镜头）？不说清楚模型会随机选，首尾帧还会选得不一样。

## 4. 写完自查

```
□ 十三要素逐条想过（可以判断不需要，不能没想到）
□ 画风轨道锁死一条，措辞没有跨轨道混用
□ 首帧确实是「现象开始之前」（用 frame-strategy.md 第 2 节的问句检验）
□ 首帧没有运动模糊
□ 产品出现处带了参考句，且紧跟在产品名词后
□ 画面内文字用「」逐字写全，数字单位标点锁死
□ 禁止项只禁 prompt 残留和具体不该有的东西，没有一刀切禁掉场景标识
□ 尾帧：除变化量和（有意为之的）构图外，与首帧逐字一致
```
