# 视频 prompt · 写法

图像承载「长什么样」，视频承载「怎么动」。本文只管后者。

---

## 1. 唯一的职责：过程

视频 prompt 回答一个问题：**从首帧的状态，怎么变成尾帧的状态？**

```
首帧图（已给）  ──→  【视频 prompt 只写这一段】  ──→  尾帧图（已给）
```

外观、场景、光线、构图**全部已经由图承载**，不需要也不应该在这里再说一遍。

## 2. 🔴 不要重复描述外观

这是本环节最大的失败模式。

> ❌ 「一个白色壁挂式充电桩，磨砂质感，正面有品牌 logo。雨水开始落下，逐渐打湿桩体表面。」

前半句是灾难。视频模型读到外观描述，会**重新想象一遍**这个产品，而它想象出来的和你首帧图里那个不是同一个——于是产品在片中缓慢漂移：logo 变形、配色偏移、比例失调。首尾帧辛苦锁死的一致性，在这一句话里全丢了。

> ✅ 「雨滴由疏到密落下，在桩体顶部聚集后沿正面成股下淌，约两秒后表面完全被水膜覆盖，下缘开始滴水。」

**只写动词和变化，不写名词的形容词。**

一个可操作的检验：把视频 prompt 里所有描述「东西是什么样」的词划掉，如果划完还剩完整的意思，就写对了。

## 3. 该写什么

按重要性排序，通常 2–5 句话就够。**视频 prompt 天然应当比图像 prompt 短得多。**

### ① 变化的主线（必写）
这个镜头的那**一个**变化量，按时间顺序说完。起点、过程、终点。

### ② 节奏与速度（必写）
「缓慢地」「在约 0.3 秒内骤然」「先慢后快」。这是视频 prompt 里最有杠杆的一句——同一个变化，节奏不同气质完全不同。

🔴 **用显式时间锚点，不要只用形容词。** Kling 官方 15 秒示例的实际写法就是逐秒点名：

> `At the 4th second, ... At the 8th second, ... In the final 3 seconds, ...`

中文同理：`在第 2 秒，指示灯亮起；在第 4 秒，红光扩散到桩体边缘；最后 1 秒保持静止。`

**卡台词、卡音效、卡剪辑点全部靠这个。** 光写「先慢后快」，模型的「快」和你的「快」不是一回事。

### ③ 次级运动（按需）
主线之外那些让画面活起来的细节：线缆的轻微摆动、扬尘的飘散、水珠的滚落、呼吸感的灯光起伏。

⚠️ 次级运动**不算变化量**，因为它没有改变状态、首尾帧看不出差别。可以放心加。

### ④ 运镜（**仅限首帧-only 的镜头**）
走首尾帧的镜头**不写运镜**，理由见 `frame-strategy.md` 第 7 节——两套指令会打架。

只出首帧时才写，用标准术语：推 push in / 拉 pull out / 摇 pan / 俯仰 tilt / 移 truck / 升降 pedestal / 跟 follow / 环绕 orbit / 手持 handheld。并给幅度：`缓慢推进，景别从中景收到近景`。

### ⑤ 避免项（按需）
针对该镜头的具体风险，不要写通用套话：

```
产品的形状、配色与 logo 全程不得改变；
充电枪线不得穿透桩体或地面；
不得出现额外的手或人物。
```

## 4. 提交正文必须是纯散文

🔴 **写进镜头表的可以带标签，提交给模型的正文不能。**

内部组织时用这四项想清楚：

```
【过程】<变化主线，按时间顺序>
【节奏】<速度与时间点>
【细节】<次级运动>
【避免】<该镜的具体风险>
```

但**提交给视频模型的正文必须摊平成一段连续散文**，且不得含以下任何东西：

| 不得注入 | 为什么 |
|---|---|
| Markdown 表格符号、代码块符号、标题符号、分隔线 | 会被当成内容处理，甚至被画进画面 |
| 方括号标签、`【】`、字段名 | 同上。模型越擅长渲染文字，这个风险越高 |
| 画面比例、分辨率、媒体用途等配置项 | 这些在界面里设，不在正文里说 |
| 镜头表其他列、确认单内容、自检表、方案说明 | 与本镜画面无关的一切 |

这不是洁癖。即梦两个头部 skill（合计 2.4 万人在用）都把这条写成硬禁令，措辞几乎一致：
「只注入分镜表内的纯镜头内容，不注入分镜表外信息，不注入 Markdown 表格符号、代码块符号、
标题符号、分隔线或确认卡内容。」

**视频模型对散文的响应也确实好于分点**，尤其在描述连续动作时——两个理由指向同一个做法。

## 5. 例（对照 `frame-strategy.md` 的雨淋镜头）

> 雨滴由疏到密落下，前半段只有零星水点在桩体顶部聚集，随后水量加大，水流沿正面成股下淌，最终整个表面被连续水膜覆盖，下缘水珠串成线并开始滴落，地面积起薄水膜。整体由慢转快，约在三分之二处达到最大雨量。线缆随水流轻微摆动。产品的形状、配色与 logo 全程不得改变。

一句形容外观的话都没有，但每一句都在推进画面。

## 6. 首帧-only 镜头的差异

没有尾帧约束时，视频 prompt 要承担更多：

| | 首尾帧 | 首帧-only |
|---|---|---|
| 变化主线 | 写 | 写，且要写清**终点是什么样** |
| 节奏 | 写 | 写 |
| 运镜 | **不写** | **必写** |
| 避免项 | 按需 | 更重要——没有尾帧兜底 |

终点没有图来锁，就必须用文字锁：`最终停在……的状态`。

## 7. 多镜头连续段：Custom Multi-Shot

连续段（`frame-strategy.md` 第 9 节）优先用一次生成出多镜头，而不是逐镜生成再拼。

两边都支持，语法不同。

**Kling 3.0 / Omni —— `Shot N (Ns):`**

官方示例**带秒数**，照抄这个形状：

> `Shot 1 (2s): Wide shot, @Boxer A and @Boxer B face off in the center of the rooftop, feet apart in a boxing stance.`
> `Shot 2 (2s): Both move in, testing each other up close...`
> `Shot 3 (3s): @Boxer A continues the attack...`

中文同构：

```
镜1（2秒）：桩体正面中景，三条监测线路从桩体向外延伸展开。
镜2（2秒）：漏电图标特写，图标点亮并闪一下黄光。
镜3（2秒）：过载图标特写，图标点亮，下方电流数值快速跳动。
```

**Seedance 2.5 —— 时间戳剧本分镜**

每段切片三行：`[开始秒-结束秒] + [核心阶段]` → `[动作等物理层面指令]` → `[镜头调度/深层意图]`。
完整公式见 `model-routing.md` 第 3 节。

### 三条注意

- **每镜仍然只写过程，不写外观**——第 2 节的规则不因为多镜头而放松
- **时长逐镜写死**，别指望模型自己均分
- **总时长受限**：Kling 3–15 秒，Seedance 单次 4–30 秒。超了要断成两次生成

## 8. 转场：看它在段内还是段尾

模型**有**做转场的能力——Seedance 2.5 官方手册专门给了转场公式，
类型包括自然镜头切换、淡入淡出、叠化、白闪·黑闪、擦除、遮罩转场。
所以问题不是「能不能」，是「该不该在这一处让它做」。

| 转场位置 | 怎么办 |
|---|---|
| **连续段内部的镜与镜之间** | **让模型做**。用官方转场公式，比外部拼接自然 |
| **交付片段的开头和结尾** | **不要做**。片段是给剪辑的素材，自带渐显渐隐会锁死剪辑点 |

### 段内转场怎么写

Seedance 官方公式（`model-routing.md` 第 3 节有完整版）：

> `切镜设定 = [转场类型指引] + [基础约束要求] + [切镜逻辑要求]`

其中**这一句每次都要带上**，它是防穿帮的：

> 禁止生硬切镜、禁止物体凭空出现。

也可以给几个选项让模型自己挑：
`请从[自然镜头切换/叠化/遮罩转场]中，根据本片风格选择最合适的一种。`

### 段尾的「画面瞬间暗下」怎么处理

需求方写「画面瞬间暗下」「淡出」，而这一镜是**整段的最后一镜**时——

> **默认生成到暗下之前为止，黑场交给剪辑。**
> 比如「红光蔓延到桩体，画面瞬间暗下」，生成的终点是**红光铺满桩体的那一帧**。

理由不是模型做不了，是**剪辑侧要留调整余地**：片段自带黑场，成片想改节奏就得重新生成。
一帧黑场剪辑一秒就能加，不值得用生成的秒数去买。

⚠️ **这是默认，不是铁律。** 需求方明确要求片段自带这个效果时照做，
但要在镜头表里写明「本片段自带黑场」，否则剪辑侧会重复加一次。

## 9. 音频与字幕

我们的配音走另外的流程，**视频生成一律不要音频**。

**Kling**：界面上关掉原生音频。按秒加价（720p 从 6 credits/s 涨到 9，1080p 从 8 涨到 12），
用不上就是白花 30% 左右。

**Seedance**：在禁止项里写死。2.5 专门优化了「随机字幕和无关 BGM 意外出现」的问题，
但仍要显式禁：

```
禁止生成字幕，禁止生成多余台词或 BGM。
```

两边都一样：**prompt 正文里不要写台词、旁白、音效描述**——写了模型会试图对口型或配音。

## 10. 写完自查

```
□ 没有任何形容外观的词（划掉形容词检验法）
□ 只推进了一个变化量
□ 节奏用了显式时间锚点（在第 N 秒…），不是只有形容词
□ 首尾帧镜头：没有运镜；首帧-only 镜头：有运镜且有终点描述
□ 长度明显短于图像 prompt
□ 避免项是针对本镜的具体风险，不是通用套话
□ 提交正文是纯散文：无 Markdown 符号、无【】标签、无比例/分辨率等配置项
□ 转场：段内该做的做了（带「禁止生硬切镜、禁止物体凭空出现」），片段首尾没自带渐显渐隐
□ 片段若自带黑场，镜头表里已写明
□ 没有写台词、旁白、音效；Seedance 侧禁止项里写了「禁止生成字幕，禁止生成多余台词或 BGM」
```
