# 需求确认与拆镜

本文覆盖流程的 ①②——从一份文案/需求，到一张确认单和一份镜头表。

---

## 1. 需求确认单

🔴 **这是整条链路唯一的硬闸门。没有用户明确同意，不许开始写 prompt。**

九个字段，逐项给出**你的建议 + 理由**，不要只列选项让用户填空。用户改哪项改哪项，不改就是默认同意。

⚠️ **画面比例每次都要问。** 不要因为上次做的是 9:16 就默认这次也是。

```markdown
## 需求确认单

**片名/用途**：
**画面比例**：<建议值> —— <理由>
**画风轨道**：<按镜分配，如 S01-S03 写实 / S04-S06 3D技术演示 / S07-S10 2D图形>
**镜头数 / 总时长**：<N 镜，约 N 秒>
**连续性归属**：<哪些镜是独立片段、哪些属于同一连续段>
**帧策略概览**：<N 镜首尾帧，N 镜首帧-only，N 镜走多镜头一次生成>
**目标视频模型**：<Kling 3.0 / Seedance 2.5，按镜分配>
**产品出现镜次**：<列镜号> —— 这些镜的 prompt 会带产品参考句，需要准备参考图
**画面内文字**：<逐条列出，数字单位标点已锁死>
**交付格式**：<分辨率 / 帧率 / 有无音频 / 字幕安全区>

**需要你拍板的**：
1. ...
2. ...
```

### 各字段的判断依据

**画面比例** —— 投放渠道决定。信息流竖版 9:16、详情页/官网横版 16:9、展会循环常用 16:9 或方图。**每次都要问，不要沿用上次的。**

**连续性归属** —— 需求方一段文案里，常常独立镜头和连续段混在一起。判据与做法见 `frame-strategy.md` 第 9 节。
**这一项定错，后面全错**：把连续段当独立镜头做，接起来一眼是拼的；把独立镜头当连续段做，白白浪费一致性成本。

**目标视频模型** —— 见 `model-routing.md` 第 3 节的分流表。确认单里要写清楚**哪些镜走哪个**，
因为混用两个模型会有质感差异，剪辑侧需要知道。

**画风轨道** —— 由内容性质决定，四条轨道见 `image-prompt.md` 第 3 节：
| 内容 | 轨道 |
|---|---|
| 安装过程、使用场景、环境 | A 写实摄影 |
| 拆解、内部结构、元器件特写 | B 3D 技术演示 |
| 图标、监测逻辑、数据、抽象概念 | C 2D 动态图形 |
| 实拍质感 + 信息叠加 | D 混合 |

同一支片子多轨道是常态，但**要提醒用户轨道切换点是剪辑上的风格断点**，切太碎会散。

**单镜时长** —— 中文配音约 **4–5 字/秒**（估算，以实际配音为准）。台词字数 ÷ 4.5 = 该镜的最短时长。

🔴 **单次生成不低于 4 秒**（Kling 下限 3s，即梦社区 SOP 下限 4s，取严的）。
按台词切出来只有 1–2 秒的分镜**不能一镜一次生成**，三条出路见 `frame-strategy.md` 第 10 节。

一个镜头**超过 5 秒还只有一个变化量**，说明变化太慢，考虑加次级运动或拆成两镜。

**画面内文字** —— 从文案里把所有会出现在画面上的字挑出来逐条列。**这一步不做，后面每张图都要回头改。**

## 2. 从文案到镜头

### 步骤

1. **切台词单元。** 按句号/语义切，一个单元 = 一句能独立成立的话
2. **配画面。** 需求方给了【分镜】【画面】标注的，用需求方的；没给的由你提案，并在确认单里标出「本镜画面为提案」
3. **验「一个变化量」。** 逐镜问：首尾之间有几件事在变？超过一件就拆。见 `frame-strategy.md` 第 5 节
4. **估时长。** 台词字数 ÷ 4.5，向上对齐原子时长
5. **定帧策略。** 按 `frame-strategy.md` 第 6 节判据。拿不准就首尾帧
6. **标产品出现。** 决定哪些镜的 prompt 带参考句

### 需求方给了粗画面时怎么办

需求方常写「（画面：动画演示桩体被雨淋被灰尘吹）」——**这是两个变化量**，按规则必须拆成两镜。

拆的时候要**主动说明为什么拆**，写进确认单的「需要你拍板的」：

> S07/S08 由原需求「桩体被雨淋被灰尘吹」拆分而来。两个现象合在一个镜头里，视频模型无法确定先后顺序，出图会互相污染。拆开后各 4 秒，总时长不变。

### 需求方给了逐句分镜时怎么办

像「【分镜：漏电图标点亮，闪一下黄光】台词：漏不漏电，」这种已经切好的，**照做，不要合并**。需求方按台词节奏切过了，合并会破坏卡点。

但仍要**逐镜验变化量**——「图标点亮 + 闪一下黄光」是一个因果链（点亮导致闪光），算一个，可以保留。

## 3. 镜头表 schema

| 字段 | 说明 |
|---|---|
| `镜号` | S01、S02… 全片唯一，拆镜后不复用旧号 |
| `时长` | 秒 |
| `比例` | 通常全片一致，特殊镜可不同 |
| `画风轨道` | A/B/C/D |
| `帧策略` | 首尾帧 / 首帧-only / 多镜头一次生成 |
| `所属段` | 独立，或连续段编号（如 `段B-1`）。同段内的镜头共用场景与布光描述 |
| `目标模型` | Kling 3.0 / Seedance 2.5 |
| `台词` | 对应的配音文字，无台词写「—」 |
| `变化量` | **一句话，只能有一个**。这是全表最重要的一格 |
| `产品出现` | 是/否 —— 决定要不要带参考句 |
| `画面内文字` | 逐字，无则写「无」 |
| `首帧 prompt` | 见 `image-prompt.md` |
| `尾帧 prompt` | 首帧的增量版；首帧-only 时写「—」 |
| `视频 prompt` | 见 `video-prompt.md` |

表格里只放短字段，三条 prompt 放在表格下方按镜号展开、各自独立代码块——**表格里塞长 prompt 会没法看也没法复制**。

模板见 `../templates/shotlist-template.md`。

## 4. 这一步的自查

```
□ 确认单七项齐全，每项都给了建议和理由，不是空着让用户填
□ 每镜的「变化量」格里只有一件事
□ 拆过的镜说明了为什么拆
□ 时长与台词字数对得上
□ 画面内文字逐字锁死，包括数字的单位与写法
□ 产品出现镜次已标出，用户知道要准备参考图
□ 连续性归属已逐段标明，没有默认全片连续或全片独立
□ 没有单次生成低于 4 秒的镜头
□ 目标模型已按镜分配，混用已说明
□ 「需要你拍板的」里每条都是真需要决策的
```
