# Codex 侧 · 出图

**仅 Codex 环境读本文。** Claude 侧交付到 prompt 与镜头表为止，不出图。

前置：`SKILL.md` 的 ①–⑤ 已完成，镜头表定稿。

---

## 1. 不做美学自审

**不要对产出的图做美学层面的自我评价和自我重出**——好不好看、气质对不对，人工会审。

但**结构和逻辑上的硬错必须自己看出来并报告**，见第 1.5 节。

模型自审在这条链路上是负收益：它会基于对自己输出的猜测反复重出，既烧钱又可能把本来对的改坏。有疑虑写在交付说明里让人看，不要自己动手改。

## 1.5 出图后校验：两类，标准完全相反

🔴 **不是「不校验」，是「校验什么」要分清。** 分界线是**能不能后期修**。

| | 不校验，不为它重出 | **必须校验，错了只能重出** |
|---|---|---|
| 内容 | logo 是否准确、品牌字样、细微材质瑕疵、轻微色偏 | **场景与物体的结构完整性和逻辑性** |
| 为什么 | 操作者用 Photoshop 修，成本远低于重出一张 | 改不动。构图和物件关系是生成时定死的 |

### 必须校验的清单

**① 「断头」检查——每一根线、每一根管，两端都要有明确去处。**
一端延伸出画外可以，但那必须是明确的走向；不能是「画到一半没了」。
读者一眼未必说得出哪里怪，但大脑会去找那根线的尽头，找不到就觉得假。

**② 每个物件都要能回答「它连着什么、靠什么固定」。**
悬空的挂钩、没有上游的线管、没有进线的配电箱、没有底座的壁挂设备——都是结构性错误。

**③ 连接关系符合物理与电气常识。**
进线和出线不能接反、线管不能弯成弧线、线缆不能穿透墙面、枪头必须能真的插进那个口。

**④ 数量与位置的自洽。**
说了五圈就该是五圈，说了左侧就不能画到右侧，说了两个箱就不能出现三个。

**⑤ 画面内的指定文字逐字核对。**
参数数字错一位就是事故，这一条和 logo 不同——它是内容不是外观。

### 判断口诀

**「PS 十分钟能修好的，不重出；PS 修不了的，必须重出。」**

logo 歪了、字体不对、有个小瑕疵 —— 修。
线缆没有尽头、配电箱悬在空中、进出线接反 —— 重出，且要改 prompt 再重出，
因为同一段 prompt 大概率会再错一次。

## 2. 出图顺序

🔴 **先出全部首帧，交给用户过一遍，再出尾帧。**

尾帧生成时要把对应首帧作为参考图一起上传（`frame-strategy.md` 第 4 节）。首帧没定，尾帧就没有可锚定的基准，出了也要重出。

```
所有首帧 ──> 用户确认 ──> 逐镜出尾帧（挂载：产品参考图 + 该镜首帧）
```

用户明确说「一次做完不用等」时可连跑，但**尾帧仍必须挂载首帧**。

## 3. 参考图库与选图（Codex 独有）

🔴 **这一节是 Codex 侧相对 Claude 侧的核心增量。**
Claude 读不到本地文件，所以它写的 prompt 里从不指定用哪张参考图。
**Codex 能读本地文件，所以选图是你的活，不是操作者的活。**

### 图库在哪

操作者把产品的多角度渲染图放在本地图库目录（默认 `assets/product/`，
操作者指定了别的路径就用他的）。开工前先列一遍目录，知道手上有哪些角度。

### 🔴 可以同时挂多张，用来合成图库里没有的角度

这是最容易被浪费的能力。图库不可能穷举所有机位，但**你不必只挑最接近的那一张**：

> 需要一个图库里没有的角度时，挂上**包夹住它的两到三张**，让模型自己推。

| 目标机位 | 挂什么 |
|---|---|
| 正面偏左 15° | 正面 + 左侧 45°（包夹） |
| 平视略仰、正面偏右 20° | 正面 + 右侧 45° + 顶视（多一张定上下关系） |
| 正面（图库里就有） | 正面一张即可，不要多挂 |
| 局部特写（面板、枪座） | 该局部的细节图 + 一张全身图（定它在整体上的位置与比例） |

两条注意：
- **包夹要真的包夹。** 目标 30° 用「正面 + 45°」，不要用「45° + 90°」——目标落在区间外就成了外推，模型会瞎猜。
- **不是越多越好。** 角度差异过大的图放在一起会互相打架；一般 2–3 张，超过 4 张收益转负。

### 选图规则

1. 先读该镜 prompt 里的**机位、方位角、景别、焦段**
2. 图库里有直接对应的角度 → 挂那一张
3. 没有 → 按上表挂包夹的两到三张
4. 局部特写 → 局部图 + 一张全身图
5. **图库里没有的东西，不要硬挂图凑数**

第 5 条是有教训的：内部结构镜（继电器、主板、芯片）在产品渲染图里**没有对应画面**，
硬挂一张外观图等于让模型去「参考」一张不存在的内部图，只会污染结果。
这类镜头的 prompt 本来就没写产品参考句——**没写参考句的镜头，不要挂产品图**。

### 图库规格（供操作者建库时参照）

| 项 | 要求 | 为什么 |
|---|---|---|
| 背景 | **实底，浅中性灰 #C0C0C0 左右**；纯白次之 | 透明 PNG 的 alpha 在多数生图管线里会被拍平，且**常拍平成黑色**，模型会读成暗环境、压暗产品。纯白则让银灰外框边缘与背景糊在一起，抠不清轮廓比例 |
| 格式 | **PNG 无损** | 产品是「高对比硬边界 + 大面积平坦色块」，正是 JPEG 振铃与块效应的重灾区，**压缩伪影会被模型当成材质纹理学进去**；logo 与小图标最先糊。必须用 JPEG 则质量 95+ 且 4:4:4 |
| 分辨率 | 长边 1500–2000px | 再大模型也会降采样 |
| 一致性 | **同一套图必须同光照、同材质、同比例** | 多图参考时不一致会互相打架，模型不知道听谁的 |
| 命名 | 角度可读，如 `pile_front` / `pile_45L` / `pile_side_R` / `pile_top` / `pile_panel` / `pile_gun` | 你要靠文件名选图 |
| 清单 | 图库里放一份 `_index.md`，逐张写明角度、焦段、有无线缆 | 文件名表达不了的信息（比如「这张是收纳态、那张是垂放态」） |

⚠️ **不要用带环境的实拍图作为唯一参考** —— 环境光会整个被带进生成结果。
实拍图适合作为**场景**参考另行挂载，与产品外观参考分开。

### 交付说明里要写清楚

每镜实际挂了哪几张图。这样人工复核时，发现产品比例不对可以直接回溯是选图问题还是 prompt 问题。

## 4. 命名与目录

```
<输出目录>/
├── shotlist.md
├── S01_a.png        # 首帧
├── S01_b.png        # 尾帧
├── S02_a.png
└── ...
```

- **纯 ASCII 文件名**（中文名会导致前端 `Failed to load file content`）
- 首帧 `_a`，尾帧 `_b`。首帧-only 的镜头只有 `_a`
- 重出的版本加 `_v2`：`S03_b_v2.png`。**不要覆盖**，人工比对时要看得到前一版

## 5. 交付说明写什么

- 哪几镜出了几版、为什么重出
- 哪些图**你觉得有问题但没改**（这是自审的正确形态——报告，不是自行修正）
- 缺参考图、prompt 有歧义等阻塞项

不要复述镜头表内容，不要给每张图写评语。

## 6. 自查

```
□ 全部首帧先出、先确认，尾帧后出
□ 尾帧挂载了对应首帧
□ 含产品的图挂载了产品参考图，且选图匹配该镜机位（必要时用包夹的两三张合成角度）
□ 没写产品参考句的镜头（内部结构镜）没有硬挂产品图
□ 交付说明里写了每镜实际挂了哪几张
□ 文件名纯 ASCII，_a/_b 规则正确
□ 重出的版本没有覆盖旧版
□ 没有做自审核重出
```
